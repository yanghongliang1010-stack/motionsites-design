# Design workflow

## Frame the real job

Before styling, record the user, primary task, fixed functionality, information hierarchy, viewport range, and accessibility constraints.

## Write a spatial thesis

Describe the page using spatial relationships. Good: “A compact command rail supports a wide, evidence-first workspace.” Weak: “A clean modern dashboard with cards.”

## Select a direction

Search with nouns for the page and adjectives for its tone. Select one primary pattern. Borrow a secondary pattern only for a specific subproblem.

## Define tokens before components

Choose type roles, surface hierarchy, semantic colors, spacing rhythm, radii, elevation, motion durations, and reduced-motion behavior. Reuse product tokens when they already exist.

## Implement by hierarchy

Build the shell and reading order first. Add styling after layout works with real content. Add motion last, after focus order and state changes are correct.

## Compare rendered evidence

Inspect desktop, intermediate, and mobile widths. Confirm that the visual center matches the user's main task and that no important controls are pushed below irrelevant empty space.
